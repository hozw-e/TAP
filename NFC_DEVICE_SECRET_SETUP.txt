===============================================================================
 NFC DEVICE SECRET - SETUP GUIDE
 How to lock down the ESP32 -> backend scan channel
===============================================================================

WHAT THIS IS
-------------------------------------------------------------------------------
The public NFC scan endpoint (backend/api/nfc/scan.php) can be protected with a
shared secret so that ONLY your ESP32 reader can submit scans. Without it, anyone
who can reach the URL could forge check-ins/check-outs, trigger guardian SMS, or
flood the endpoint.

The protection is OPT-IN. It is controlled by two values that MUST match:

  1. NFC_DEVICE_SECRET  -> an environment variable on the BACKEND (server)
  2. DEVICE_SECRET      -> a constant in the FIRMWARE (esp32.ino)


CURRENT STATE (as deployed)
-------------------------------------------------------------------------------
- Backend:  NFC_DEVICE_SECRET is EMPTY/UNSET  ->  the check is DISABLED.
- Firmware: DEVICE_SECRET = ""                ->  no secret header is sent.

Because the backend secret is empty, the device check is skipped entirely.
The existing ESP32 firmware works WITHOUT any change. Nothing is required
right now. You do NOT need to re-flash the scanner to deploy the other changes.


THE GOLDEN RULE:  BOTH OR NEITHER
-------------------------------------------------------------------------------
The server secret and the firmware secret must ALWAYS be in the same state:

  - BOTH empty      ->  check disabled, everything works (current state)
  - BOTH set + equal ->  check enabled, only the real device is accepted

NEVER set only one side:

  - Server set, firmware empty   ->  the scanner gets 401 Unauthorized on every
                                     tap. Attendance stops working.
  - Server empty, firmware set   ->  harmless, but pointless (header ignored).

So when you turn this on, change BOTH at the same time.


HOW TO TURN IT ON (when you are ready, with physical access to the ESP32)
-------------------------------------------------------------------------------
Step 1. Generate a long random secret (32-64 chars). Examples:
          - PowerShell:  -join ((48..57)+(97..102) | Get-Random -Count 48 | % {[char]$_})
          - Or any password generator (letters + numbers, no spaces/quotes).
        Keep it private. Treat it like a password.

Step 2. Set it on the BACKEND environment.
          - Local XAMPP:   add to the root .env file:
                             NFC_DEVICE_SECRET=your_generated_value_here
          - Railway (prod): add an environment variable on the backend service:
                             NFC_DEVICE_SECRET = your_generated_value_here
          (Use the SAME value in every environment the scanner talks to.)

Step 3. Set the SAME value in the firmware (esp32.ino), near the top:
          const char* DEVICE_SECRET = "your_generated_value_here";

Step 4. Re-flash the ESP32 with the updated esp32.ino (Arduino IDE -> Upload).

Step 5. Verify:
          - Tap a registered card -> it should still record normally.
          - (Optional) From a browser/curl, POST to /api/nfc/scan.php WITHOUT the
            X-Device-Secret header -> it should return 401 "Unauthorized device".


HOW TO TURN IT OFF / ROTATE THE SECRET
-------------------------------------------------------------------------------
- To DISABLE again:  set NFC_DEVICE_SECRET empty on the backend AND set
                     DEVICE_SECRET = "" in esp32.ino, then re-flash.
- To ROTATE (change the value): pick a new secret, update BOTH the backend env
                     and esp32.ino to the new value, then re-flash. Do them close
                     together to minimize downtime (the scanner will 401 in the
                     gap where only one side has the new value).


RELATED FILES
-------------------------------------------------------------------------------
- backend/utils/device-auth.php   -> the server-side check (requireDeviceAuth)
- backend/config/database.php      -> defines NFC_DEVICE_SECRET from the env
- backend/api/nfc/scan.php         -> calls requireDeviceAuth() before processing
- esp32.ino                        -> DEVICE_SECRET constant + X-Device-Secret header
- .env                             -> where NFC_DEVICE_SECRET lives for local dev

NOTE: .env is git-ignored, so the secret is never committed. Set the production
value directly in the Railway dashboard, not in a committed file.
